# What I did
    I allowed secured remote access to my VM.

# What worked vs what is stuck
    I had a problem. In fact, I created an previous VM. VMWare attributed the same ip address to my current VM but the host key changes.So SSH thought that it's an attack. I had to remove the old key from the host's known_hosts.
    I understood that the fingerprint / host key was created automatically during the installation of the OS, and the public/private keys pair was created by the host.

# My reasoning
    The SSH protocol saves us from the man-in-the-middle attack. But it cannot distinguish with the host key mistake.

# My solution
    SSH connection from the host to the VM without password but with keys.

# Commands
    * **ip a** to search ip addresses
    * **ssh <ton_user>@<IP_de_la_VM>** for remote access
    * **ssh-keygen -t ed25519 -C "netlabops-host"** to create public key on the host
    * **ssh-copy-id <ton-user>@<IP_de_la_VM>** to copy the public key as authorized key to the VM
