# What worked vs what got stuck
    ## What worked
        * With chmod 600 on ficher.txt, labuser got Permission denied. The file only gives rw- to its owner, and labuser fails into the "others" category.
        * On a directory without x, ls still listed the names, but cd failed.
        * cat /etc/shadow without sudo returned Permission denied.
    ## What got stuck (and what I corrected)
        * I first believed that x on a file lets you modify it. That is wrong: w allows modifying a file, x allows running it as a program.
        * I confused the output of ls -la with the format of a line in /etc/passwd. They are two different things (see below).
        * I first thought /etc/passwd- stored the passwords. It is only an automatic backup copy of passwd, and it is world-reachable too.
        * The first attempt to run test.sh before chmod +x failed with: <Permission denied>

# Key concepts
    ## Permissions (rwx for owner / group / others)
        | Permission | On a file | On a directory |
        | :----: | :---: | :---: |
        | r (read) | read the content | list the names inside |
        | w (write) | modify the content | create or delete entries inside |
        | x (execute) | run it as a program | traverse it (cd, access what it contains) |
    The directory case is the most surprising one: r without x lets you see the names but not access anything.

    ## ls -la vs /etc/passwd
        * ls -la shows: file type and permissions, number of links, owner, group, size, modification date, name.
        * A line of /etc/passwd contains: username, password placeholder, UID, GID, comment field (GECOS), home directory, login shell.
  
    ## Why passwd and shadow are separate
        * /etc/passwd is 644: it must stay readable by everyone, because many programs use it to map a user ID to a username (for example, ls -l displays the owner name this way).
        * Since it cannot be locked down, the password hashes (not the plain-text passwords) live in /etc/shadow, which is 640 and readable only by root and a restricted group.
        * Principle: separate what everyone needs to read from what must stay secret.
  
    ## sudo 
        Working as root permanently is dangerous. sudo grants elevated privileges only for the command that needs them, for example writing in /etc or accessing another user's files. It it not needed for my own files in my own home directory.

# Commands used
    pwd                         # print current directory
    ls -la                      # list files with permissions, owner, group
    cd /etc                     # change directory
    mkdir ~/test-perms          # create a directory
    touch fichier.txt           # create an empty file
    chmod 644 fichier.txt       # rw-r--r--
    chmod 600 fichier.txt       # rw-------

    sudo adduser labuser        # create a user
    su labuser                  # switch user
    cat /etc/passwd             # world-readable user database
    cat /etc/shadow             # denied without sudo
